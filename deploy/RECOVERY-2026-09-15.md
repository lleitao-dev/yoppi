# Yoppi staging security recovery — 2026-09-15

## Status

Closed.

The compromised staging host was replaced rather than cleaned or reused. Yoppi staging now runs on a newly provisioned and hardened host using the immutable v0.11.0 release.

## Incident

The previous staging web container showed confirmed unauthorized execution on 2026-09-08.

Observed indicators included:

- old staging host: `134.122.116.23`
- malicious executable: `/tmp/.kworkerd (deleted)`
- SHA-256: `5241d67a93c752d90605f203f96b452adaa7b5fcc13f09ed5ad7ddd5cbfa3f4b`
- observed outbound destinations:
  - `193.32.162.73:443`
  - `45.86.86.254:443`

The old host was treated as untrusted and was not used as a recovery source.

## Database

The long-running application uses the least-privileged `yoppi_app` PostgreSQL account.

The recovery also identified a v1.0 requirement: schema migrations must execute separately from the long-running application credential. Production application startup must not require DDL privileges.

## Credential and infrastructure closeout

Recovery closeout included:

- staging SSH deployment key rotation
- managed PostgreSQL administrative password rotation
- new application database credential
- new object-storage credential
- old object-storage access key revoked
- old compromised Droplet destroyed

No production or backup environment file was copied from the compromised host.

## Residual hardening work

At incident closure, the following items were tracked separately from recovery:

- production migration credential separation
- application/container egress restrictions
- pinning the Caddy image immutably
- reducing production image build/runtime contents where practical
- expanding public security acceptance testing

These are v1.0 hardening tasks and did not block closure of the September 2026 recovery.
